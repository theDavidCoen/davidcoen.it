## Redirect checklist for static-at-root migration

If WordPress moves to `/legacy/`, add **301 redirects** at minimum for:

1. Every URL in **“referenced by new static site”** — keep exact paths (`/news/`, `/feed/`, `/category/...`)
2. All **blog post slugs** at root (`/{slug}/`)
3. **Archive pagination** (`/news/page/N/`, `/page/N/`, `/category/.../page/N/`)
4. **Shop** paths if old links still matter (`/shop/`, `/shop/{product}/`, `/cart/`, `/checkout/`, `/my-account/` or `/mio-account/`)
5. Legacy utility pages still bookmarked (`/contact/`, `/payment-processor/`, `/private-key-recovery/`, old `/privacy-policy/`)

Catch-all pattern (LiteSpeed/Apache example):

```apache
# After static files, send legacy WP paths to /legacy/
RewriteEngine On
RewriteRule ^(news|feed|category|shop|cart|checkout|contact|payment-processor|private-key-recovery|comments)(/|$) /legacy/$0 [L,QSA,PT]
# Per-post slugs: maintain a map or redirect via WP under /legacy/ + RewriteCond on known slugs
```

> **Note:** A catch-all for every post slug requires either enumerating slugs (this list) or keeping WP routing active via reverse-proxy/rewrite to `/legacy/index.php`.
